# 豆格 · 拼豆工作室（账号登录版）

照片转纯色拼豆网格，支持坐标、可编辑色号、用量清单、PNG/CSV 导出、裁剪、电脑滚轮和手机双指缩放。每格按多数颜色取色，不混色；照片在浏览器本地处理，不上传服务器。

本版本增加服务端登录保护：未登录时不会返回工具 HTML。每个人有独立账号，只允许管理员创建；无公开注册。管理员可以停用/启用账号、重置密码。用户无权操作账号管理接口。退出登录会撤销服务端会话，停用和密码重置会使该用户原有会话失效。工具顶部含退出登录按钮。

## 将现有 Netlify 网站升级为登录版

这是带 Netlify Functions 的应用，不能继续把单个 HTML 或 ZIP 拖入 Drop 当作完整版部署；那样无法创建后台函数。使用**原有 Netlify 项目**连接本仓库，从 Git 构建发布，可保留网站地址和站点级账号数据。

1. 在现有 Netlify 项目的配置中连接 GitHub 仓库 `wrui88917-tech/pindou1`，部署包含本版本的分支。
2. 构建设置由 `netlify.toml` 提供：Node 22；构建命令 `node build-auth.mjs`；发布目录 `public`；Functions 目录 `netlify/functions`。平台先按 lockfile 安装依赖。
3. 在 Netlify 的环境变量中，**私下填写**以下值，确保对 Functions 运行时和 Production 环境生效：
   - `ADMIN_USERNAME`：管理员账号，默认 `admin`；3–32 位英文字母、数字、点、横线或下划线，不区分大小写。
   - `ADMIN_PASSWORD`：管理员密码，8–128 个字符。
   - `SESSION_SECRET`：至少 32 位随机字符，用于签名会话，不与密码重复。
4. 重新构建部署。在 Functions 页面确认 `auth`、`users`、`studio`、`admin` 已部署。生产环境运行需 HTTPS。
5. 打开网站，使用上述管理员账号登录，进入账号管理，添加独立用户，再将账号和初始密码通过可信渠道告知对方。
6. 用无痕窗口验证：未登录打开 `/studio` 会跳到登录页；普通用户可以使用工具，但访问 `/admin` 或账号接口会被拒绝；停用后不能再登录；新密码可用、旧密码不可用。

账号和会话保存在 **Netlify Blobs 的站点级 `bead-accounts` 存储**，不会写进网页或公开仓库，不使用部署级临时存储。用户密码采用随机盐 + scrypt，管理员密码保存在 Netlify 环境变量。修改管理员密码/用户名或会话密钥将使原管理员或全部相关会话失效。部署到另一个站点不会自动迁移账号。

如果账号配置或存储不可用，服务器拒绝访问，不会绕过登录。账号数据、会话和限速计数均使用强一致读与条件写；同一 IP 每 15 分钟最多尝试登录 10 次。会话有效期 8 小时。到期会话记录不再有效，数据库管理时可以定期清理过期记录。账号管理规模按手工维护的小型图库设计，不含邮箱验证、自助找回、付款或照片云存储。

已经加载到浏览器里的工具可在本地运行，停用会阻止后续服务端访问，并在页面恢复可见或最多 60 秒的在线检查后退出；网页登录不能收回用户已保存的旧离线 HTML 或阻止已授权用户复制前端。旧静态站点没有登录门槛，只有完成新部署后线上才受保护。

## 本地开发与验证

Node.js >=20（部署固定为22），使用现有 checkout，无需额外 worktree。

```sh
npm ci
npm test
```

`npm test` 会先构建 HTML，然后执行算法测试和登录/权限测试。管理员登录、账号创建、停用、重置密码、会话撤销、角色权限、跨站请求、限速及公开路径检查均有测试。

本地启动前，在运行进程的环境中安全设置 `ADMIN_USERNAME`、`ADMIN_PASSWORD` 和 `SESSION_SECRET`（名称见 `.env.example`，不含真实值；不会自动读取 `.env`），再执行：

```sh
npm start
```

默认端口 3000，可用 `PORT` 覆盖。本地使用 `.local/accounts/` 文件存储模拟数据库，不连接生产账号；该目录已忽略，不应提交。密码和密钥未配置时显示登录页但拒绝登录。生产由 Netlify 注入 Blobs 连接，不需要手工设置 Blobs token。

## 离线图纸功能

- 横向 16–200 格，纵向最多 320 格，保持裁剪后的宽高比。
- 相近 RGB 颜色以 8 级步长归并后在格内投票，选取多数色；有限颜色模式再映射到代表色。无品牌豆子色卡映射。
- 每格一个纯色，坐标从 1 开始，5 格加粗；可显示完整色号，编号支持 1–8 字符编辑，不可重复。
- PNG 包含中文尺寸/颜色数/颗数摘要和配色清单，CSV 使用相同编号。可选将近白色区域视为空格；关闭此选项时白色仍计为白豆。透明区域以及板外填充始终为空格。
- 双指/滚轮缩放与拖动只改变显示，不改变格数。手机支持的浏览器可使用系统分享，其他情况下载 PNG。
- `node build-standalone.mjs` 可生成无登录离线 HTML，仅供独立离线使用，**不要将其作为登录版站点的公开文件部署**。生产发布目录只包含登录页与非敏感静态资源。

## 配色编号批量操作

配色清单提供“清空全部编号”“智能填充编号”和“撤销编号操作”。清空允许空编号，也可逐个手动留空；重新生成图纸时保持空编号模式，上传新照片则恢复默认编号。智能填充在本地按中性色、色相和明暗排序，生成 1、2、3 等唯一短编号，不调用 AI 服务、无需 API 密钥，也不代表任何品牌的真实豆子色号。原图颜色、格数及用量不变，格内文字、PNG 和 CSV 使用同一套编号。可以撤销最近一次批量编号操作；上传新照片会清除撤销记录。


## 实体拼豆板尺寸与已有图纸导入

板型预设为 52×52（2704 格）、78×78（6084 格）、108×108（11664 格），也可自定义 1–200 列 / 行。自由尺寸保留原有照片转换工作流。选择板型后，照片按比例放入板内，图案居中，外围填充为空格；板总格数与实际豆子数量分别显示。输出坐标按整块板从 1 开始，摘要注明图案左上角位置。

导入已有图纸时，选择“已有拼豆图纸”，填写原图的列数和行数（例如示例小熊是 35 列、39 行），可按图例填写颜色总数（例如 9）。裁剪要紧贴真实格子区，去掉标题、外围坐标和底部图例；“校准网格 / 查看原图”叠加绿色取样网格供人工对齐。裁剪支持 0.1% 步进。此模式对每格内部取多数色，减少原图格线与文字干扰，不会自动 OCR 识别 H7、A5 等原始品牌色号；请在配色清单手动填写。

图纸模式默认勾选“白色区域留空”，近白（各 RGB 分量 >=240、最大差值 <=16）区域不计为豆子；如果图案包含真实白豆，应关闭此选项再人工核对。透明度低于 10% 的像素占一格至少一半时，该格为空。白背景与真实白豆无法仅凭颜色可靠区分，未承诺自动识别。

已有图案默认按一格对应一颗豆居中放置，不缩放、不裁掉多余格子；超出板型时提示选择更大板。只有主动勾选“超出板尺寸时等比缩小”后才会重新采样，可能丢失图案细节。例图 35×39 共 1365 格，804 颗与 561 空格是不同统计概念；在 52×52 板内，外围空格也不计入用豆数。

“下载 PNG 图纸”包含坐标、完整色号、摘要与图例，供对照实体板拼豆；“纯色网格 PNG”每格 12×12 像素、无标题/坐标/文字/图例，空格保留透明，便于其他软件按明确行列数再次导入。未实测 AI豆仓等第三方软件的专有导入格式、自动识别或色号匹配兼容性，导入时仍需在对方软件中校准行列。PNG 无法携带可编辑色号的结构化语义；需要保留品牌文字时请使用带图例图纸并在目标软件核对。

验证包含棋盘取色去边框、透明空格、35×39 原格居中放入 52×52、三个预设容量、超限保护及显式缩小，并在桌面和 390px 手机模拟中测试校准、白色留空、实际用豆计数和透明网格 PNG 导出。测试使用合成图纸，不代表用户示例小熊已完成实图识别或第三方导入验证。
